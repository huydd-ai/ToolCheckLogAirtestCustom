# Per-Test Summary Report Design

## Problem

The per-test HTML report (generated by Airtest `LogToHtml`) is functional but lacks:
- A prominent PASS/FAIL indicator — status is not immediately visible at a glance
- Step filtering/search — no way to quickly find failed steps
- Summary statistics — total/pass/fail counts not prominently displayed

Additionally, the status must be guaranteed correct: if any individual step has status FAIL, the overall test status MUST be FAIL.

## Approach: Custom `report_summary.html`

Generate a standalone summary HTML alongside the existing Airtest report. Keeps the Airtest report intact for deep inspection, while providing a fast-loading overview with clear status and search/filter.

## Files Changed

### 1. `step_capture.py` — Add `duration` field

The `_hooked_run_step` already records `start` and `end` timestamps. Store computed `duration` (end - start, rounded to 2 decimals) in the step dict.

| Field | Type | Example |
|-------|------|---------|
| `name` | str | `"cold start with parameters"` |
| `action` | str | `"cold_start_with_combined"` |
| `status` | str | `"PASS"` or `"FAIL"` |
| `screenshot` | str\|None | `"1781510575796.jpg"` |
| `behaviour` | str\|None | `"Mission not complete"` |
| `duration` | float | `3.25` |

### 2. `reporting.py` — Add `generate_summary_report()`

New function that writes a self-contained `report_summary.html` to the test output folder.

**Signature:**
```python
def generate_summary_report(
    out_dir: Path,
    tc_name: str,
    steps: list[dict],
    status: str,
    recordings: list[Path],
    error_top: Exception | None = None,
) -> Path
```

**Report layout (top to bottom):**

1. **PASS/FAIL Banner**
   - Full-width bar, height ~120px
   - FAIL: `#ff7b72` bg, white bold text "FAIL"
   - PASS: `#56d364` bg, white bold text "PASS"
   - Below: test name (monospace), timestamp
   - Right side: recording badge (if MP4 exists) linking to `recording_*.mp4`

2. **Stats Card**
   - Horizontal row of stat boxes: Total Steps, Passed, Failed, Duration
   - Each box: number (large) + label (small)
   - If FAIL: failed count highlighted in red
   - Duration formatted as `Xs` or `Xm Ys`

3. **Step Table**
   - Headers: #, Step Name, Action, Status, Screenshot, Duration, Error/Behaviour
   - Filter bar above table: [All] [Pass] [Fail] buttons + search text input
   - Rows colored: PASS = green tint, FAIL = red tint
   - Status column: small colored badge (same `pass`/`fail` classes as aggregate report)
   - Screenshot column: thumbnail (max 80px wide) with tooltip/link to full image
   - Error column: truncated text, expandable on hover/click
   - Clicking a FAIL row: expand inline to show full error message + full-size screenshot

4. **Error Detail Panel** (visible only when FAIL)
   - Section below table showing first failed step details
   - Full error message
   - Full-size screenshot for the failed step

**Styling:**
- Dark theme matching aggregate report CSS
- Inline `<style>` block (no external files)
- Inline `<script>` for filter/search/expand interactivity
- All CSS/JS self-contained in the HTML

**Status correctness guarantee:**
```python
overall_status = "FAIL" if error_top or any(s["status"] == "FAIL" for s in steps) else "PASS"
```
This same logic is already used in `write_log_txt()`. The banner color and status text both derive from this single computation — if a step is FAIL, the banner will always be red.

### 3. `runner.py` — Call `generate_summary_report()`

After `generate_html()` succeeds, call the new function. Insert after line ~84:

```python
try:
    summary_path = generate_summary_report(out_dir, air_path.stem, steps, status, recordings, error_top)
    print(f"[INFO] summary report: {summary_path.name}")
except Exception as e:
    print(f"[WARN] Failed to generate summary report: {e}", file=sys.stderr)
```

## Status Correctness Verification

Already correct in `runner.py:76-77` and `reporting.py:9`. The summary report derives status from the same `steps` list and `error_top`. No code path exists where a step FAIL results in a PASS banner.

## Error Handling

- Missing screenshots: show placeholder "No screenshot" text
- Missing recording: no recording badge shown
- Empty steps list: show "No steps captured" message
- All exceptions caught and logged as WARN — never blocks the run

## Testing

- Unit tests for `generate_summary_report()`: verify HTML output has correct status banner, step count, filtered content
- Verify the report renders correctly both via `file://` and HTTP server
- Manual verification: run a test with intentional failures and confirm FAIL banner + red rows
